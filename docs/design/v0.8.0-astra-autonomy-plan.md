## 0. 세 줄 요약

1. **규칙 층은 이미 자율이고, 스킬·역할 가이드 층은 구세대 비계다.** `rules/verify-route.md`는 R1~R3을 자동 실행으로 두고 R4만 사람에게 넘기며, `rules/self-loop.md`는 "되묻지 말고 진행"을 요구한다. 그런데 91개 스킬에는 "May I write?"가 106건(66개 스킬), 45개 역할 가이드 중 41개에는 "당신은 자율 실행자가 아니다. 사용자 승인을 기다려라"가 복붙되어 있다. 두 층이 정반대를 말한다.
2. **Astra는 이 모순을 해결하지 않고 무시한다.** OpenAI 공식 지침은 "행동으로 기울고, 명백히 파괴적·비가역적일 때만 확인, 작업 전에 정지 규칙을 미리 줘라"이고, Codex 하네스 프롬프트(비공식)는 "스킬·마크다운 파일의 요구사항 예외를 자동으로 사용자 승인 대상으로 취급하지 말라"고 명시한다. 스킬이 요구하는 승인은 하네스 수준에서 이미 기각되므로, 남는 것은 노이즈와 스킬 전체의 신뢰도 하락뿐이다.
3. **고칠 것은 문구가 아니라 정지 기준이다.** "언제 멈추는가"를 6개 조건으로 못 박은 자율 계약을 한 곳에 두고, 스킬·역할·린터·훅이 그 계약을 따르게 정리한다. 안전선(R4·유료 호출·확정 결정 번복 금지·정책 게이트 exit 2·팩 혼합 금지·쓰기 소유)은 한 줄도 풀지 않는다.

**2026-09-09 추가 근거.** 사용자가 전달한 OpenAI 사장 인터뷰 영상 요약은 한 축을 더한다. 승인 과잉만이 아니라 **절차 지시 자체가 Astra에서는 마이너스**일 수 있고, 남는 가치는 프로젝트에 축적된 맥락·시행착오·검증 자산이라는 것이다. 이 계획은 그 축을 § 3.3과 D10(측정 파일럿)으로 받되, v0.8.0 범위는 승인 과잉 제거(Phase A~C)로 한정한다.

**이 계획이 외부 근거에서 가져오는 것은 둘이다.**

1. **정지 기준을 "파괴적·비가역적" 한 축에 둔다.** 이 저장소가 이미 `rules/verify-route.md`에서 "되돌리기 비용(R1~R4)"으로 정의한 축과 같다. 새 원칙을 들여오는 것이 아니라 기존 원칙을 스킬 층까지 내려보내는 일이다. (공식 지침)
2. **승인 과잉만이 아니라 지시 과잉이 문제다.** 절차를 단계별로 적어둔 스킬 본문 자체가 Astra에서는 성능을 깎을 수 있다. 반면 프로젝트에 축적된 맥락과 시행착오 기록은 남는 가치다. 이 축은 § 3.3에서 다루고, 검증 없이 일반 규칙으로 강제하지 않는다(`docs/policy-updates.md`: 한 번의 추측은 규칙으로 강제하지 않는다). (영상 요약, 2차 자료)

## 3. 진단

### 3.1 문제의 구조 (네 층이 서로 다른 모델을 전제한다)

```
하네스 (Astra)      "스킬 파일의 승인 요구는 자동 승인 대상이 아니다"   ← 이미 자율
규칙 층 (rules/)    R1~R3 자동, R4만 사람 · 루프 중 묻지 않음          ← 이미 자율
스킬 층 (skills/)   모든 쓰기 전 "May I write?" · Phase마다 승인        ← 구세대 비계
역할 층 (roles/)    "자율 실행자가 아니다 · yes를 기다려라"              ← 구세대 비계, 게다가 서브에이전트에게
린터·게이트         Check 4가 ask 문구를 보상 · P4가 자율 산출물에 경고   ← 비계를 고정하는 나사
```

세 가지 결과가 생긴다.

1. **모순 지시.** `skills/dev-story/SKILL.md:211`은 서브에이전트에게 "implement this story and write the test"를 명시하고, 같은 프롬프트에 붙는 `gameplay-programmer.md:42`는 "Wait for yes before file editing"이다. 한 프롬프트 안에서 충돌한다.
2. **서브에이전트의 질문은 갈 곳이 없다.** 질문만 반환하고 종료하면 오케스트레이터가 추측하거나 사용자와 왕복하는데, 왕복마다 스토리+GDD+ADR 원문+매니페스트 패키지를 재적재한다. `CLAUDE.md`가 인용한 610K vs 134K 측정과 같은 메커니즘이다. 이 저장소는 이미 `rules/subagent-collaboration.md` § 3·§ 3.1에서 "질문이 아니라 결정 항목과 산출물 경로를 반환하라"고 설계했다. 역할 가이드만 그 설계와 어긋난다.

### 3.3 두 번째 축: 지시 과잉. 무엇이 비계이고 무엇이 해자인가

영상 요약이 더한 관점은 "묻지 않게 하라"를 넘어선다. **사람이 적어둔 절차가 모델의 일반화보다 못하면 절차 자체가 마이너스**라는 것이다. 이 저장소에 대입하면 자산은 두 부류로 갈린다.

| 부류 | 이 저장소의 자산 | 판정 |
|---|---|---|
| **비계(어떻게 할지 지시)** | 91개 SKILL.md 합계 22,274줄, 평균 245줄, 400줄 이상 13개, 최대 987줄(`ux-design`). Phase/Step 헤딩 478개. 역할 가이드의 Collaboration Protocol 36%. 매 세션 훅이 넣는 규칙 요약 25줄(이 저장소 실측). 옵션 위젯 64건 | 줄일 후보. 단 어디까지가 "모델이 알아서 하는 것"인지는 측정 전에 모른다 |
| **해자(무엇이 참이고 어떻게 증명하는지)** | 결정적 게이트(`scripts/*.py`, exit code 계약), 워크플로 카탈로그의 산출물 글롭과 의존, `production/track.txt`·`technical-preferences.md`·ADR·확정 결정 절, 레슨(`Documents/Lessons/`), `human-actions.md`, 세션 상태, `docs/policy-updates.md`의 재발 방지 규칙, 역할 가이드의 도메인 이론·체크리스트·금지 패턴(64%) | 유지하고 투자한다. 영상이 말한 "축적된 맥락과 시행착오 데이터"가 정확히 이것이다 |

이 구분이 플러그인의 무게중심을 옮긴다. **"모델에게 절차를 가르치는 플러그인"에서 "프로젝트의 사실·결정·증명 방법을 들고 있는 플러그인"으로.** 스킬은 산출물 계약(무엇을 어디에 만들고 무엇으로 끝났다고 판정하는가)이지 절차 대본이 아니어야 한다.

다만 이 저장소의 원칙은 측정 없는 일반화를 금한다. 스킬 본문 축약이 실제로 Astra의 결과를 좋게 하는지는 **같은 스토리를 현행 스킬과 축약 스킬로 각각 돌려 비교**해야 안다(§ 6 Phase D). v0.8.0 범위는 § 6 A~C(승인 과잉 제거)이고, 지시 과잉 축은 파일럿으로 시작한다.

"결과물을 일일이 검토하기보다 더 많이 뽑는다"는 관점은 이미 D5(디렉터 게이트를 스폰 대신 자기검토+결정적 게이트로)와 `rules/self-loop.md`(생성 → 채점 → 수정 반복)를 뒷받침한다. 사람의 검토 시간을 아끼는 대신 그 자리에 exit code가 들어간다.

```markdown
### Working Protocol (subagent)
You run as a Codex subagent: no user is in this conversation. The orchestrator has
```

### 9.2 구현형 (20파일)

**before** (`implementation-agent-protocol.md:8` "not an autonomous code generator. The user approves all… file changes" · `:33` "STOP and ask" · `:39` "May I write this to [filepath(s)]?" Wait for yes)

```markdown
### Working Protocol (subagent)
No user is in this conversation. The story, ADR, manifest, and your write-owned paths
arrive in the prompt. Implement from them; do not ask for what they omit.
- **Ambiguity → assumption, not a stop.** Choose the option matching the ADR and
  engine/stack conventions, write it as `Assumption:` in the report, proceed.
- **Write code and tests in owned paths without asking.** List every file touched.
  Undo is `git revert` of your commit, or the listed file set.
- **Never silently deviate** from the GDD/PRD or ADR: implement the closest compliant
  form and return the deviation as a decision item (problem / recommendation /
  alternatives / evidence).
- **Withheld from you**: migrations on real data, deletions, anything published, paid
  calls, changing a fixed decision → decision item, not action.
  → `rules/verify-route.md` § 1 (R4) · `rules/decision-lifecycle.md` § 4
- **Return**: gate results with exit codes, files + status, assumptions, decision items,
  residual risks. Not the code body. → `rules/subagent-collaboration.md` § 3.1
- Cannot run the tests or gates → `BLOCKED: <what>` on the first line.
```

### 9.3 리더십형 (3파일)

**before** (`leadership-agent-protocol.md:8` "the user makes all final strategic decisions" · `:38` "This is your call" · `:131` "May I proceed with documentation?")

```markdown
### Working Protocol (subagent)
You are consulted as a director in a separate conversation: the user is not here.
Return a verdict and a recommendation the orchestrator can act on or put to the user.
- **Gate calls: verdict token on the first line** (`[GATE-ID]: PASS|CONCERNS|…`),

- **Strategic forks: recommend, do not defer.** One recommendation with the trade-off
  you accept, 1-2 alternatives with what each sacrifices, evidence (pillars, prior
```

## 11. 이 계획 자체에 우리 규칙을 적용하면

- **라우트**: heavy(다분야, 증거 요구). 검토 4팀 병행, 쓰기 소유 없음(전원 읽기 전용), 통합 소유자 1명. `rules/subagent-collaboration.md` § 2.1 준수.
- **검증 등급**: 이 문서 자체는 R1(문서 1개, 한 번의 삭제로 되돌림). 계획이 제안하는 변경은 R2.
- **claim-confidence**: 외부 인용 3건 모두 확인 상태를 표기했다(§ 1). 검토 수치 중 휴리스틱은 (추정)으로 표시.
- **decision-lifecycle**: D1~D9는 사용자가 채택하기 전까지 ⏳이며, 채택되면 소비 프로젝트가 아니라 이 저장소의 CHANGELOG와 `docs/design/`에 기록한다. 재검토 트리거: Astra 이후 모델에서 "묻지 않고 진행"이 사고를 낸 실측이 나오면 D2·D3를 다시 연다.
