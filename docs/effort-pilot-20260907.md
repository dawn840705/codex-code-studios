# 실제 모델 파일럿: 2026-09-07

후속 요청 “다음 단계 진행”에 따라 ChatGPT 로그인 CLI로 제한된 실제 모델
파일럿을 실행했다. 주간 계정 사용률이 95%여서 원래 제안한 27회 대신
**동일 작업 × 3 arm × 1회**, 회당 60초, 자동 재시도 0회로 제한했다.
모델은 기존 설정의 `gpt-6-astra`로 고정하고 이 세 실행의 effort만 바꿨다.
API 키 호출·추가 크레딧 구매·리셋 크레딧 사용·전역 설정 변경은 하지 않았다.

수정 비용은 이 수치에 포함하지 않았다. 생산 모델 적용값은 세 실행 모두
`applied_effort=null`이다. 출력 토큰에서 추론 토큰을 분리할 수 없었다.

CLI 완료 이벤트의 실행 합계는 input 133,275 + output 308 = **133,583 tokens**다.
cached input을 다시 더하지 않았다. 이 값은 **실행 부분합**이며 부모의 조사·
분류·구현·검증 준비 사용량까지 포함한 총사용량/청구 비용이 아니다.
총사용량, 실제 청구액, 절감률은 미확인이다.

계정 주간 사용률은 전후 95% → 96%로 조회됐다. 부모 대화와 다른 계정 작업도
포함하는 정수 단위 계정 지표여서 파일럿만의 비용으로 환산할 수 없다.
추가 반복은 이번 배치에서 하지 않았다.

  이전 단계의 미커밋 구현은 측정 대상 snapshot에 넣지 않았다. 실행기/검증기는
  외부에서 동일 파일로 적용하고 그 내용 해시를 고정했다.
- 작업: 실제 `skills/*/SKILL.md` 일반 파일 개수를 세어 정수 하나만 답하기.
  사전 정답은 모델 호출 없이 snapshot 파일 열거로 계산했다.
- 모델/지원 effort: 설치 CLI 0.153.4의 bundled model catalog로 확인.
- seed `20260907`, 실제 순서 **High → Auto → Medium**. 모든 arm에 동일 prompt,
  read-only sandbox, 사용자 config/규칙/설치된 플러그인을 적용했다.
- **회귀 테스트가 병행 실행되어 시간에 부하 교란이 있다.** 이 측정의 시간은
  관찰치로만 남기고 속도 우열/절감률 판정에 사용하지 않는다. 다음 성능 실험은
  회귀 검증 완료 후 단독 실행한다.
- arm당 1회, 기계적 작업 하나뿐이다. 성공률 개선·Low 최적성·일반 개발 작업의
  비용 절감을 판단할 수 없다. 모델 alias/서버 부하/공유 cache도 완전 통제되지 않았다.
- 세 실행 모두 같은 비치명적 CLI 진단을 받았다: 설치된 0.7.0의 SessionEnd
  timeout이 3초로 제한됨, 스킬 설명이 context budget에 맞게 축약됨.
  종료 이벤트와 독립 검증은 정상이다. 현재 설치 문맥을 포함한 파일럿이며
  새 관찰 훅의 앱 내 로딩을 검사한 실험은 아니다.

**결론:** 실제 모델 작업까지 전달기와 독립 검증이 연결됨을 확인했다.
현재 데이터는 auto가 고정 effort보다 낫다는 근거가 아니다. 기본 정책은 보정하지 않았다.

## 추가된 실행기와 검증

`tests/effort_pilot.py`는 오프라인 `prepare`, 명시적 `run`, 독립 `verify`를
제공한다. 기존 batch 디렉터리를 덮어쓰지 않고, snapshot/실행기 해시가 달라지면
거부한다. 배타적 dispatch 표식으로 같은 배치를 재실행하지 않는다. executor
장애나 파일 변경을 발견하면 나머지 arm도 중단한다.

```bash
python3 -m pytest -q tests/test_effort_pilot.py tests/test_reasoning_effort.py
# 58 passed in 2.33s; exit 0
python3 -m pytest -q tests/
# 647 passed, 5 skipped, 40 subtests passed in 47.20s; exit 0
```

새 검증기는 진행 메시지나 명령 출력의 `91`을 정답으로 오인하지 않는다.
정상 완료 이벤트와 마지막 agent_message의 정확한 정수를 검사한다.
테스트에서 틀린 답/설명 첨부/진행 출력/실패 이벤트, 서로 다른 snapshot,
중복 실행을 거부하는 것도 확인했다.
