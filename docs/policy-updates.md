# 프로젝트 경험을 공통 방침에 반영하는 절차

2026-09-07 사용자 직접 지시로 채택. 프로젝트를 진행하며 확정된 운영 원칙과 검증된 재발 방지 절차를 Code Studios 원본에 지속 반영한다. 일정에 없는 기능 개발이나 예약 자동화를 시작하라는 지시는 아니다.

## 무엇을 반영하는가

- 사용자 확정 원칙 중 다른 프로젝트에도 적용할 수 있는 작업·검증·인계 절차.
- 실제 실패와 수리 결과로 확인한 재발 방지 규칙. 한 번의 추측은 일반 규칙으로 강제하지 않는다.
- 기존 규칙의 모순·누락·중복을 해소하는 변경. 같은 의미가 이미 있으면 그 위치를 참조한다.

제품별 기획·수치·에셋 채택·현재 작업 순서·팀 역할 계약·로컬 절대 경로는 소비 프로젝트에 둔다. 비밀정보나 비공개 작업 내용을 공통 문서에 복사하지 않는다. 사용자의 명시 지시와 프로젝트 계약을 공통 기본값으로 덮어쓰지 않는다.

## 어디에 어떻게 반영하는가

1. 원본 저장소와 대상 프로젝트의 `AGENTS.md`, 브랜치, worktree, 변경 상태를 확인하고 쓰기 소유 경로를 정한다. 다른 세션과 겹치는 파일은 편집하지 않는다.
2. 기존 내용을 검색한다. 행동 규칙은 `rules/`, 실행 절차는 해당 `skills/*/SKILL.md`, 설명은 `docs/`, 재사용 양식은 기존 `templates/` 또는 `docs/`의 해당 템플릿을 갱신한다. 새 문서는 기존 위치로 표현할 수 없을 때만 만든다.
3. 근거가 된 문제나 사용자 결정, 적용 범위, 바뀐 행동을 최소한으로 남긴다. 기록물 구분은 [work-records](../rules/work-records.md)를 따른다. 같은 사건의 상세 기록은 원 프로젝트에 두고 참조한다.
4. 규칙 파일은 자동으로 읽힌다고 가정하지 않는다. 관련 스킬 또는 `AGENTS.md`에 필요한 읽기 지점을 연결한다. 소비 프로젝트에는 원본 저장소 위치와 이 절차의 참조를 둔다.
5. 변경에 맞는 검증을 수행한다. 문서만 바뀌면 diff·링크·기존 계약과의 정합성을 확인하고, 실행 동작이 바뀌면 해당 검증기를 실행한다. 릴리스 검증은 원본 `AGENTS.md`의 필수 검사를 따른다.
6. 대상 파일만 커밋하고 프로젝트 결과에 반영 위치·검증·원본 SHA를 남긴다. 원본 접근 불가나 쓰기 충돌이면 남은 반영 위치와 이유를 인계한다. 새로 반영할 내용이 없으면 빈 기록을 만들지 않는다.

## 공통 작업 기준

- 공유 파일 변경 직전에 대상이 깨끗한지 검사하고, 예상하지 않은 변경을 발견하면 그 파일에 쓰지 않는다. 상태 출력만 하고 다음 쓰기를 무조건 실행하는 방식은 검사로 보지 않는다.
- stage·검사·commit·push는 각각 성공한 경우에만 다음 단계로 진행한다. 특히 PowerShell에서 native 명령의 실패는 줄바꿈만으로 후속 실행을 막지 않으므로 종료코드를 확인한다.
- 공유 저장소의 커밋은 다른 세션이 즉시 사용할 수 있다. 자기 push 여부로 미공개를 추정하지 말고 정정은 새 커밋으로 남긴다. 이력 재작성은 명시 승인과 협업 상태 확인이 있을 때만 수행한다.
- 완료 보고는 실제 수행한 검증에 한정한다. 정적 검사, 엔진 실행, 사람의 시각 채택을 구분하고 미실행 검증을 통과로 기록하지 않는다.
- worktree는 진행 중인 작업과 명시된 재개·비교 기준에만 유지하고, 중단·보관 작업은 브랜치와 필요한 산출물로 보존한다. 유지 개수는 실제 동시 작업과 저장 공간에 맞춰 정하며 프로젝트별 권장 개수를 공통 상한으로 강제하지 않는다. 일부 경로만 필요한 새 레인은 sparse-checkout을 사용하고, 기존 활성 레인의 구성을 임의로 바꾸지 않는다.
- 불필요한 worktree·완전 병합 브랜치 정리를 마감 절차에 포함한다. 삭제는 프로젝트의 사용자 승인 범위 안에서 통합 담당 한 세션이 순차 수행한다. 깨끗한 미병합 worktree도 비활성 확인과 로컬·원격 커밋 보존을 마치면 폴더만 회수할 수 있다. 미병합 브랜치는 유지하고, 삭제 직전 경로·HEAD·변경·무시 파일·잠금을 다시 확인한다. 검증한 절대 경로에 `git worktree remove`를 사용하며 실패를 강제 삭제로 우회하지 않는다.
- 미커밋·미추적·무시 파일이 있는 worktree는 기본적으로 보존한다. 별도 승인된 정리 범위에서 회수하려면 추적 파일의 staged·unstaged 변경과 미추적·무시 산출물을 모두 복구할 수 있게 보관하고, 파일별 해시 대조와 staged·unstaged 복원 시험으로 검증한다. 복구 보관물은 비밀정보를 포함할 수 있으므로 로컬에 보존하며 자동으로 Git에 추가하거나 원격으로 올리지 않는다. 활성·용도 불명·보존 지정 레인은 회수하지 않는다.
- 브랜치 삭제 전 실제 원격 기준과 로컬 통합 브랜치 양쪽에 tip이 직접 포함됐는지, 어떤 worktree에서도 checkout되지 않았고 활성·보존 지정이 없는지 재확인한다. 원격 tip이 바뀌면 중단하고 로컬 삭제는 `git branch -d`를 사용한다. 기본·보호·출시 브랜치와 패치 동등성만 있는 체리픽 브랜치는 자동 삭제하지 않는다. 브랜치는 커밋 참조이므로 삭제 자체가 객체 용량 회수를 보장하지 않으며, 정리 효과는 실측으로 보고한다.

- 2026-09-08: 혼합 줄바꿈 raw CSV의 Git 정규화·checkout 해시 변화를 실제 복구로 확인해 [Shared asset recovery](rules/artifact-organization.md#shared-asset-recovery)에 원본 바이트 필요 경로의 사전 정규화 제외·인덱스 재수납·새 경로 checkout 후 독립 원본 SHA 대조를 추가했다. 원본 두 파일의 복원 해시 일치와 통합 검증을 근거로 하며, 제품별 이력·수치는 원 프로젝트에 유지한다.

## 원본과 설치본

원본 저장소가 수정돼도 설치된 플러그인 캐시는 자동으로 바뀌었다고 간주하지 않는다. 캐시를 직접 수정하지 않고 정상 배포·설치 경로를 이용한다. 결과에는 원본 반영과 설치 적용을 따로 표시하며, 이 문서 작성 자체는 릴리스나 설치 갱신을 뜻하지 않는다.
